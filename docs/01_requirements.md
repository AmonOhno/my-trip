# My Trip — 要件定義書

## 1. プロダクト概要

**My Trip** は「旅の記録を自動で残す」ことに特化したパーソナル旅行ログアプリ。

ユーザーは旅の始まりに **「旅開始」** ボタンを押すだけ。あとはアプリが位置情報(およびiOSではHealth情報)を使って、その日に訪れたスポット・移動経路・歩数などを自動で記録する。**「旅終了」** を押せば記録は確定し、いつでも当時の足取りを地図とタイムラインで見返せる。

### コンセプト
- **記録はゼロ操作**: 旅の間、スマホを取り出す必要はない
- **思い出は地図とタイムラインで**: 「どこに・いつ・どれくらい居たか」を自動整理
- **完全無料**: 有料API・有料サーバーを一切使わない構成

## 2. ターゲット / ユースケース

| # | ユースケース |
|---|---|
| UC-1 | 旅の朝に「旅開始」を押し、観光中は一切操作しない |
| UC-2 | カフェや神社などに10分以上滞在すると「スポット」として自動記録される |
| UC-3 | 移動中の経路(徒歩・電車など)がトラック(軌跡)として残る |
| UC-4 | 「旅終了」を押すと1つの旅として保存される |
| UC-5 | 過去の旅を一覧から選び、地図上の足取り+タイムラインで振り返る |
| UC-6 | スポットに写真・メモ・タイトルを後から付け足せる(任意) |
| UC-7 | 旅データをJSONでエクスポート/インポートしてバックアップできる |
| UC-8 | 次の旅の計画(期間・行きたい場所)をつくっておき、当日は計画から旅をはじめる |

## 3. 機能要件

### 3.1 旅の記録(コア)

| ID | 要件 | 優先度 |
|----|------|--------|
| F-01 | 「旅開始」で記録セッションを開始する | Must |
| F-02 | 位置情報を定期取得し、軌跡ポイントとして保存する(目安: 15〜30秒間隔 or 20m移動ごと) | Must |
| F-03 | **滞在スポット自動検出**: 半径約80m以内に10分以上とどまった場合、スポットとして記録する(Stay Point Detection) | Must |
| F-04 | スポット名を無料の逆ジオコーディング(OpenStreetMap Nominatim)で自動付与する。失敗時は「スポット N」と仮名を付ける | Must |
| F-05 | 「旅終了」でセッションを確定し、旅一覧に追加する | Must |
| F-06 | 記録中にアプリを再起動しても記録セッションが復元される | Must |
| F-07 | 記録中の現在状態(経過時間・距離・スポット数・現在地)をライブ表示する | Should |
| F-08 | (iOS) HealthKitからその旅の期間の歩数・歩行距離を取得して旅に紐付ける | Should |
| F-09 | (iOS) バックグラウンドでも位置記録を継続する(Background Location) | Must (iOS) |
| F-10 | (Web) タブが前面にある間は記録継続。バックグラウンド制限はPWAの制約として明示 | Must (Web) |
| F-11 | (iOS) 記録中でも旅メモの編集・写真の添付ができる(写真はV-07と同様に端末内にのみ保存) | Should |

### 3.2 振り返り(ビュー)

| ID | 要件 | 優先度 |
|----|------|--------|
| V-01 | 旅一覧: 日付・タイトル・スポット数・総距離・所要時間をカード表示 | Must |
| V-02 | 旅詳細: 地図(OpenStreetMap)に軌跡ポリライン+スポットピンを描画 | Must |
| V-03 | タイムライン: 「移動 → 滞在 → 移動…」を時系列で表示(滞在時間・移動距離付き) | Must |
| V-04 | スポットの編集: 名前・メモの変更、スポットの削除 | Should |
| V-05 | 旅タイトル・旅メモの編集、旅の削除 | Should |
| V-06 | 統計表示: 総距離・総時間・スポット数・(iOSは歩数) | Should |
| V-07 | (iOS) 旅にフォトライブラリの写真を添付できる(グリッド表示・拡大・削除)。写真は端末内にのみ保存する | Should |

### 3.3 データ管理

| ID | 要件 | 優先度 |
|----|------|--------|
| D-01 | 全データは端末ローカルに保存(Web: IndexedDB / iOS: SwiftData)。サーバー不要 | Must |
| D-02 | JSONエクスポート / インポート(共通スキーマ、Web⇔iOS間で互換) | Should |
| D-03 | (iOS) 終了した旅をアーカイブして一覧・ホームから分離できる(アーカイブ一覧から戻せる) | Should |

> 注: 写真(V-07)・アーカイブ状態(D-03)・計画(P-05)は `my-trip-export/v1` スキーマに**含めない**(スキーマ不変・Web互換維持)。エクスポートは従来どおり旅・軌跡・スポットのみ。

### 3.4 旅の計画

| ID | 要件 | 優先度 |
|----|------|--------|
| P-01 | 旅の計画(タイトル・期間・メモ)を作成・編集・削除できる | Should |
| P-02 | 計画に「行きたい場所」(名前・メモ・任意の位置)を追加・編集・削除・並べ替えできる | Should |
| P-03 | ホームに進行中・これからの計画を表示し、計画一覧(期間中/これから/過去)へ遷移できる | Should |
| P-04 | 計画から記録を開始できる(計画タイトルを引き継ぎ、計画と旅を紐づける)。計画から記録済みの旅へ遷移できる | Should |
| P-05 | 計画データは端末ローカルのみに保存し、`my-trip-export/v1` スキーマには含めない | Must |
| P-06 | 計画詳細に地図を表示し、位置つきの行きたい場所を番号ピンで示す。一覧の行やピンをタップするとその場所へ地図が寄る | Should |
| P-07 | 行きたい場所を地図から登録できる: 無料の地名検索(Web: Nominatim `/search` / iOS: `MKLocalSearch`)の候補から選ぶ、または地図をタップして座標を指定する(名前は逆ジオコーディングで自動補完)。位置は任意項目で、名前だけの場所も引き続き登録できる | Should |

> 計画のスコープ外(将来候補): 記録中画面での計画チェックリスト、計画のエクスポート対応、行きたい場所と記録済みスポットの自動照合

## 4. 非機能要件

| ID | 要件 |
|----|------|
| N-01 | **コスト0円**: 地図タイルはOSM、逆ジオコーディングはNominatim(利用ポリシー遵守: 1req/秒以下、キャッシュ必須)、ホスティングは静的(GitHub Pages等)、バックエンドなし |
| N-02 | プライバシー: 位置情報は端末外に送信しない(逆ジオコーディングの座標送信のみ。設定でオフ可) |
| N-03 | オフライン耐性: 記録はオフラインでも動作(逆ジオコーディングのみ後回し)。Web版はPWAとしてインストール可 |
| N-04 | バッテリー: iOSは `desiredAccuracy` と距離フィルタで消費を抑制 |
| N-05 | アクセシビリティ: WCAG AAを目標(コントラスト・キーボード操作・ARIA) |
| N-06 | 言語: 日本語UI |

## 5. スコープ外(v1では作らない)

- アカウント/クラウド同期(コスト0制約のため)
- 写真の自動取り込み(iOS v2候補: PhotoKitで旅期間の写真を提案)
- 交通手段の自動判定(徒歩/電車/車の分類)
- SNS共有・公開機能

## 6. プラットフォーム方針

| | Web版 | iOS版 |
|---|---|---|
| 技術 | TypeScript + React + Vite (PWA) | Swift + SwiftUI |
| 位置情報 | Geolocation API (`watchPosition`) | CoreLocation (Background Updates) |
| Health | 不可(制約として明記) | HealthKit(歩数・距離) |
| 地図 | Leaflet + OpenStreetMap | MapKit(Apple純正・無料) |
| 保存 | IndexedDB (idb) | SwiftData |
| 配布 | 静的ホスティング(無料) | App Store(開発者プログラム$99/年のみ、コード側コスト0) |

## 7. 主要フロー

```
[ホーム] --旅開始--> [記録中]
   ^                    | 位置を定期取得 → 軌跡保存
   |                    | 80m以内に10分滞在 → スポット確定 → 逆ジオコーディング
   |                    v
   +----旅終了----- [旅確定] ---> [旅一覧] ---> [旅詳細(地図+タイムライン)]

[ホーム] ---> [計画一覧] ---> [計画詳細(期間・行きたい場所)]
                                  | この計画で旅をはじめる(タイトル引き継ぎ・紐づけ)
                                  v
                               [記録中](以降は上のフローと同じ。計画詳細から旅の記録へ遷移可)
```

## 8. 用語定義

| 用語 | 定義 |
|---|---|
| 旅 (Trip) | 「旅開始」〜「旅終了」の1セッション |
| 軌跡ポイント (TrackPoint) | 定期取得した位置座標+時刻 |
| スポット (Spot) | 滞在検出により確定した「訪れた場所」 |
| セグメント (Segment) | タイムライン上の1要素(移動 or 滞在) |
| 計画 (TripPlan) | 旅の前につくる予定(タイトル・期間・メモ)。記録した旅と紐づけできる |
| 行きたい場所 (PlanItem) | 計画に並べる訪問予定の場所(名前・メモ・任意の位置) |
