# CI(GitHub Actions)

PR の作成・更新時(`opened` / `synchronize` / `reopened` / `ready_for_review`)に次の 2 つのワークフローが動きます。

| ワークフロー | ファイル | 内容 |
|---|---|---|
| E2E | [.github/workflows/e2e.yml](../.github/workflows/e2e.yml) | `web/` でユニットテスト(vitest)と Playwright のスモーク E2E を実行。1件でも失敗すればジョブ `e2e` が失敗(NG) |
| Claude Code Review | [.github/workflows/claude-code-review.yml](../.github/workflows/claude-code-review.yml) | Claude Code 公式 `code-review` プラグインで PR をレビューし、指摘を PR にコメント |

E2E は `main` への push でも実行します。

## E2E(web/)

- 場所: `web/e2e/`、設定: `web/playwright.config.ts`
- 本番ビルド(`npm run build` → `vite preview`)に対して Chromium(モバイル表示)で実行
- 対象フロー: ホーム表示と計画・設定への遷移 / 旅をはじめる→記録中→終了→旅詳細(タイトル編集・一覧反映・リロード後の永続化)/ 計画作成と場所検索による行きたい場所の追加 / 設定の全データ削除ダイアログ
- **全件パスを厳密に**: `retries: 0`(CI でも `--retries=0`)。リトライで通った flaky も不合格扱い。`test.only` は CI で禁止(`forbidOnly`)。テストのスキップ・無効化で緑にしないこと
- **外部通信はモック**: OSM タイルと Nominatim は `web/e2e/fixtures.ts` でモック応答し、それ以外の外部ホストは遮断。位置情報は Playwright の geolocation で固定座標を注入
- 失敗時は Playwright のレポート・トレースを Artifact `playwright-report` として保存

ローカルで CI と同条件で実行:

```bash
cd web
npm ci
npx playwright install chromium   # 初回のみ
CI=1 npx playwright test --retries=0
```

### iOS を E2E の対象外にしている理由

iOS の UI テスト(`MyTripUITests`)は Xcode とシミュレータが必要で macOS ランナーでしか動かせません。
macOS ランナーは Linux の 10 倍の分単価で無料枠を急速に消費し(プライベートリポジトリ)、
シミュレータ起動・ビルドで 1 回 15〜30 分かかるため PR ごとの実行には不向きです。
加えて位置情報・HealthKit の権限ダイアログ処理が必要で不安定になりやすく、「リトライなしで全件パス」の
条件と相性が悪いため、現状は対象外とします。ロジックの正しさは Web 版と同一アルゴリズム
(`web/src/core/stayPoint.test.ts`)のユニットテストで担保し、iOS の UI テストはローカルで
CLAUDE.md 記載のコマンドで実行してください。

## 手動で行う設定

### 1. Claude GitHub App のインストール

<https://github.com/apps/claude> から本リポジトリにインストールします
(Claude Code から `/install-github-app` を実行しても設定できます)。

### 2. Secrets の登録

Settings → Secrets and variables → Actions → New repository secret で、**どちらか一方**を登録します。

| Secret | 取得方法 |
|---|---|
| `ANTHROPIC_API_KEY` | Anthropic Console で発行した API キー(従量課金) |
| `CLAUDE_CODE_OAUTH_TOKEN` | ローカルで `claude setup-token` を実行して発行(Claude Pro/Max のサブスクリプション枠を利用) |

> コスト0円制約との関係: アプリ本体ではなく開発用 CI の設定です。追加課金を避けるなら
> サブスクリプション枠を使う `CLAUDE_CODE_OAUTH_TOKEN` を推奨します。
> fork からの PR ではシークレットが渡らないため、レビューはスキップされます(ワークフローの `if` 条件)。

### 3. ブランチ保護で E2E を必須チェックにする

Settings → Branches(または Rules → Rulesets)で `main` に対して:

1. 「Require a pull request before merging」を有効化
2. 「Require status checks to pass before merging」を有効化
3. ステータスチェックに **`e2e`** を追加(一度 PR でワークフローが走ると候補に表示されます)
4. 必要に応じて「Require branches to be up to date before merging」も有効化

Claude Code Review はコメントによる助言なので、必須チェックには含めない運用を想定しています。
